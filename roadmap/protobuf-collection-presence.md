## Scoped owner proposal

Remove the caller-selected `req` flag from `wrapperAttribute` and `wrapAttr`.
The wrapper constructor derives contents requiredness from the resolved wrapped
kind: arrays/maps have value contents (nil is protobuf's empty representation),
while primitive and union contents retain their presence check. This is a private
normalization contract, not a new DSL rule. All root, named, anonymous nested,
union branch and endpoint-shape consumers use that constructor; anonymous shape
allocation must hash the same normalized contract it emits. Do not implement
three unrelated `req=false` call-site repairs or weaken all wrappers.

The existing named collection path unwraps alias chains, retains its established
identity and marker, and is already the correct behavioral control. The fix does
not change collection field tags, protobuf wire schema, or conversion layout.
It removes an invented validation predicate. Any unexpected schema/name change
must be explained by the comparison and resolved before final review. Existing
length predicates must still run on nil contents; they are not presence checks.
The generated named MinLength1 control already rejects empty binary contents
with a length error, and both request/result conversions already return nonnil
empty collections after binary decode. No converter change is currently needed.

## Implementation discovery: wire shape is not validation identity

The initial type-derived wrapper correction exposes a hidden parent defect:
Rich contains both unconstrained nested integer arrays and a MinLength1 nested
integer array. Both normalize to `ArrayOfSint64` with the same generated UID,
because `protoAttributeShape` records wire fields/requiredness but excludes
length and other predicates. The validator collector then keeps the first
identity. The parent emits a presence-only helper and silently ignores a later
stricter contents contract; removing invented presence yields an undefined
helper call for that later constrained occurrence. The shared #819 eligibility
repair does not resolve this (verified by production overlay at 6b21d37fd).

A parent-source overlay of the five touched files, with the stricter anonymous
minimum set to 2, compiles/vets and incorrectly accepts `Nonempty: [][]int{{1}}`.
The durable generated probe is
`grpc/codegen/tla/collection_contents/masked_contract_probe.go.txt`; exact parent
source and test overlay is `/tmp/loom-684-parent-contract/overlay.json`, failure
log `/tmp/loom-684-parent-contract-red.log` (2.506s). Candidate compile failure
is `/tmp/loom-684-candidate.log`; #819 overlay repeats it in
`/tmp/loom-684-with819.log` (1.166s). These are distinct from nil conversion.

Production expansion was paused for owner reassessment. Do not emit empty stubs,
merge unrelated bounds, or add per-consumer checks. The generated wrapper's
shared identity must distinguish contracts if its named validator owns contents
predicates; alternatively occurrence predicates need a complete shared owner
separate from wire declaration identity. Merely hashing wire shape is inadequate.
Explicit named-message sharing is a separate boundary and must not be silently
changed while repairing generated anonymous collection wrappers.
