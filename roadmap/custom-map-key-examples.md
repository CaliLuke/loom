# Automatic examples for custom map keys (#884)

The design may admit a custom comparable representation for a logical Bytes key.
Automatic examples still synthesize logical `[]byte` values and insert them into
a Go map before the custom representation exists. Length-constrained maps have a
second copy of this assumption. Collection reflection can also encounter an
unrepresentable nested map before an example can be omitted.

## Sequence and acceptance

- [x] Reproduce direct, length-constrained, alias and nested collection failures;
  retain explicit examples and native noncomparable-key admission controls.
- [x] Give collection example construction one representation boundary. Omit an
  automatic example when its logical Go container cannot be safely constructed;
  do not guess application custom types, recover from panics or reject valid DSL.
  Share map candidate construction between ordinary and constrained paths while
  preserving their existing sampling and length behavior.
- [x] Verify custom-key service generation compiles and remains deterministic;
  ordinary examples/generated artifacts stay identical. Preserve authored
  examples and recursive collection placeholders where representable.
- [ ] Run focused example/expr and generated-code checks, obtain independent
  exact-diff review, then deliver one owning-ticket commit and close the report.

This is a synthesis correction, not a new representation admission rule. Missing
automatic examples already have an established nil result for values the
generator cannot synthesize. Application-authored examples remain authoritative.

The shared logical reflection owner returns nil before constructing an invalid
map type, propagating through containing maps and arrays. Interface key values
also pass a dynamic comparability check. One map candidate loop serves both
ordinary fixed draws and constrained distinct-key counts, retaining bounded
retries and omission when constraints cannot be satisfied. Explicit examples
still return before synthesis. No custom application type is guessed.

Bounded acceptance uses the original comparable `[16]byte` service and extends it
with empty, bounded, nested and authored forms. It generates and compiles through
the existing example-module harness. Existing nested-map query, object-key body
and recursive named-array testdata designs exercise unchanged representations;
parent/candidate generated bytes and an independent-process repeat are compared.
Direct tests cover alias and dynamic interface keys, preserve authored values,
native-key admission, allocation bounds and recursive placeholders. This is a
deterministic representation correction with no new concurrency or protocol state.
