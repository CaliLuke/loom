The defect is the streaming decode branch in writeWebSocketRequestCase: it
returns a request-local error to Recv for notifications. Unary decode and streaming
endpoint errors already complete locally. ReceiveWebSocketRequest cannot safely
suppress all dispatch failures because error-response writes use that channel.

The intended owner is shared WebSocket request-error completion in the generated
typed dispatch boundary: classify request-local failure before it becomes the
connection-level return. All unary/streaming decode and endpoint error branches
must derive the same suppression/send/error-return decision. Typed error encoders
remain method-specific; transport read/context/write failures remain terminal.

Existing CompleteStreamError owns final service-stream responses and emits a
stream-close suppression event. Reusing it blindly for invalid params would add
an unrelated lifecycle event. Preserve the existing invalid-params observer reason;
readiness must choose the smallest shared owner without duplicating policy or
silently broadening observation semantics. #723 optional diagnostic callbacks,
batch envelopes, invalid-envelope policy and result-ID mutation are separate.

## Selected owner proposal for independent review

Use one private request-failure completion renderer in
`jsonrpc/codegen/stream_sections_websocket_request.go`, consumed by the three
existing failure sites: streaming decode, streaming endpoint and unary adapter.
Each error has already been classified as request-local at those sites. The
renderer emits: no HasID -> return nil; otherwise s.SendError(ctx, req.ID, err),
returning only an error-response send failure. It contains the actual policy;
it is not a pass-through helper or per-method exception. All three branches can
use s.SendError directly; the streaming wrapper currently only delegates to that
same method with the same original ID. Delete their duplicated completion code.

Keep ReceiveWebSocketRequest unchanged: its dispatch error type does not identify
request failure versus native writes, so suppressing there loses real failures.
Keep CompleteStreamError for the public service-stream final-response API; that
owner additionally emits a final-response-suppressed event. Dispatch rejection
must preserve invalid-params observation without inventing a stream-close event.
No exported runtime API or alternate error taxonomy is needed for this ticket.
