# Semantic memo ownership and publication

`MemoLifetime` compares compilation-global memo retention with memo tables owned
by immutable supplied values, occurrence captures and representation plans.
These are the owners in `expr/value_resolve.go`, `expr/value_synthesis.go` and
`expr/value_projection.go`. Identity is never regenerated by eviction: copies of
a live owner share its table. The context retains authored-example provenance
associations, but no longer roots every temporary resolution, capture or plan.

## Bounds, assumptions and results

The model has three owners, two keys per owner and two workers. Each worker
performs one lookup; both can contend on the same key. External handles can be
dropped before or after creator publication and reader completion. Atomic table
admission installs one pending slot, publication completes it, and readers can
observe only completed slots. For projection, completion represents success, failure or panic fallback;
concrete failure contents are outside the model. Resolution is serialized rather
than slot-based, and synthesis caches completed/suppressed attempts only. A
synthesis callback panic can still retry as before and is outside this model
(the once-per-key invariant is not a claim about panicking synthesis callbacks).

Retention means reachability eligibility under a tracing collector, not when Go
will collect an object or return memory to the OS. The owner-reference relation
is an explicit design assumption checked separately by concrete GC tests. The
model assumes independent owners, terminating callbacks and atomic admission;
reentrant callback cycles and cross-cache key correctness are not proved.

- `Global.cfg` reproduces compilation-global retention: `NoUnusedRetention`

From this directory:

```sh
java -Xmx512m -cp "$TLA_JAR" tlc2.TLC -workers 1 \
  -metadir "$TLC_STATE" -config Owned.cfg MemoLifetime.tla
```

Repeat the two negative configurations, requiring their named invariant failures.
Keep TLC states, traces and raw logs outside the repository.

## Go correspondence

`value_memo_lifetime_test.go` retains the context while releasing supplied values,
synthesized capture graphs and projected plans. All three failed against the
compilation-global implementation and pass with owner-local memo tables. The
weak pointers are test observations only; production does not use weak caches,
finalizers, eviction or forced GC. The tested pointer-bearing objects are not
subject to Go's tiny pointer-free allocation batching. Runtime GC calls and
KeepAlive establish the intended test roots, not an application latency promise.
See the [Go weak-pointer contract](https://pkg.go.dev/weak).

Direct tests preserve live source/result identity, role/source/scope isolation,
plan-copy and subplan projection reuse, independent-plan callback counts and
concurrent resolution/synthesis/publication. Existing custom projection and
semantic contract tests cover failure/codec/branch behavior beyond the model.
A live source can retain sibling resolutions; a live capture retains its scoped
sampling results; a subplan can retain the original plan association graph.
Authored-example sources still held by the context retain their resolution tables.
These intentional roots limit reclamation; no total-memory bound is claimed.
