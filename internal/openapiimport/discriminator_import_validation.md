# Discriminator import validation

This record covers #1005 import and its shared exporter/runtime qualification. The acceptance rule is that an
admitted hint preserves schema membership, alternative multiplicity, source
identity, annotations and every captured HTTP occurrence. An exact envelope may
use Loom's existing tagged representation only when it regenerates those facts;
other admitted cases retain the full-object union. Hints never select a branch
for validation or add required fields. Rejected source forms remain fatal under
lossy import.

The initial implementation was developed in an isolated source copy. Its #1014 parent
was initially the actual commit `4d5daba25d622d881a9ff1cdce35602880b5d0d4`.
That earlier composed source included the independently reviewed amendment at
`c86613180fbba9eb232f9969f95d18a9427ebe72`. Its #957 input was prospective
source, not a delivered commit. Scratch validation does not
establish prerequisite delivery or authorize publication. Exact input manifests,
commands, raw failures and candidate hashes are supplied in the review packet.

## Property presence and extension admission

Discriminator property presence combines object-only type membership with the
shared conditional `required` implication. Nullable alternatives and nullable
parents therefore remain optional even when their object values require the
member. The conditional implication itself remains unchanged for oneOf sibling
redundancy, and an outer nullable union wrapper does not retarget its inner hint.
`TestDiscriminatorNullableAlternativeAdmission`,
`TestDiscriminatorNullableParentAdmission`, `TestSchemaPropertyGuarantees`,
`TestNullableRequiredSiblingRemainsRedundant` and
`TestDiscriminatorNullableAdmissionGenerates` cover admission through generation.
The [property-guarantee model](tla/discriminator_admission/README.md) records
counterexamples to required-only, conflated and wrapper-owned classification.

Discriminator `x-*` values enter the existing `analyzer.extensions` owner after
versioned grammar validation. They share JSON compatibility diagnostics and
normalized JSON values with other extension locations; nonfinite values fail
analysis rather than appearing first as render failures.
`TestDiscriminatorExtensionAdmissionOwner` covers nested invalid values and
normalized numbers/objects. No separate discriminator extension policy exists.

## ParentHint selection refinement

A valid source ParentHint can have direct children only in unselected operations.
Source admission therefore uses the complete typed canonical allOf graph, while
projection coherence uses retained schema occurrences. Representable named
implicit children are declaration dependencies, not validation dependencies.
Their complete strong closure is admitted by the existing planner. Unsupported
implicit children keep child-owned diagnostics; explicit mapping and local
fallback targets remain strong dependencies.

If a selected projection cannot emit any child evidence, strict import reports
`schema-discriminator-projection`. Partial import may omit only the hint, with
`schema-discriminator-omission` in `OperationOmissions`; required fields and
parent membership remain unchanged. A detached declaration copy prevents one
operation from mutating another. Reports are reconciled against the final
combined output, which may retain an inline child from a second operation.
Neither generated names nor explicit mappings are invented to force retention.
This is an execution refinement of the accepted ParentHint contract, not a new
validation rule for the original parent schema.

At the historical r5 prospective-source checkpoint, direct identity/projection
controls and scoped lint pass. The isolated partial-parent generated contract
passes generation, compilation, JSON/YAML libopenapi validation, membership
comparison and independent-process bytes. Two generated boundaries were red:
otherwise-unused imported implicit children are absent from exported components,
and explicit JSON query unions reference un-emitted transport types (also for
plain unions without hints). The required regressions remain unskipped. Those shared exporter/generator corrections are now implemented; the current
qualification below supersedes this checkpoint. The earlier green generated
matrix predates these strengthened cases and is not substituted for them.
The rejected tentative JSON-query tagged widening is absent from the source;
query envelopes remain FullObject under the existing native parameter grammar.

## Root-owned obligation and shared walk correction after R2 re-review

The R2 re-review reported two LOW findings and a naming nit. First, partial
import silently dropped a valid weak child whose only unwitnessed obligation was
a hint already emitted by the selected strong graph. The hint could come from an
explicit/default target or a selected operation. Re-adding the child was

A weak child now answers only for obligations it introduces beyond the strong
root graph. Strict import still reports the root hint, and partial import still
reports one omission for it. Introduced obligations, including mutually
introduced ones, still reject. One selected-root walk per round serves every
reached candidate, with one witness inventory. Unreached candidates are dropped
without changing the walk. `pruneComponents` retains the converged walk. Strict
outputs that succeed are unchanged: a root hint with a witness never decided
eligibility. Only outputs with an unwitnessed root hint gain the dropped
children, as in the explicit/default expectation update. The opt-in model and
direct tests are described with the discriminator model README.
